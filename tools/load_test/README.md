# Нагрузочный сценарий панелей S-06

Сценарий работает с изолированной БД, синтетическими участниками и двумя разными
учётными записями с правом `participants.view`. Проверено с Locust 2.47.0.
Укажите в окружении `RS_LOAD_PANEL_1_LOGIN`, `RS_LOAD_PANEL_1_PASSWORD`
и соответствующие переменные для панели 2. Для локального CA задайте `RS_LOAD_CA`
с путём к PEM. Для сырых измерений задайте `RS_LOAD_SAMPLES` с путём к CSV,
`RS_LOAD_RUN_ID` и `RS_LOAD_SCENARIO`.

Локальный smoke двух панелей из корня репозитория:

```sh
locust -f tools/load_test/panels.py --headless -u 2 -r 2 -t 15s --csv panel-smoke --host http://127.0.0.1:8000
```

## Подключение сценария Б2

Запускать в одном процессе Locust, перечислив оба файла через запятую в `-f`.
Добавить абсолютный путь `tools/load_test` в `PYTHONPATH` для импорта `s06_metrics`.
`PanelOne` и `PanelTwo` занимают по одному месту, остальные три пользователя —
терминалы Б2. Агенты слушают задания отдельно от этих пяти пользователей.
Перед запуском графика терминалов вызвать `wait_for_panels(timeout=10)`. Отрицательный результат означает сбой подготовки прогона.
Длительность запуска включает прогрев и минимум 5 с на доставку после последнего подтверждения.

Терминалы используют схему `register_one(run_id, terminal_index, external_id)`,
где `terminal_index` принимает значения 1–3. После успешного scan и непосредственно
перед отправкой confirm:

```python
from time import perf_counter

from s06_metrics import record_confirmation_started, wait_for_panels

# При старте сценария, перед отсчётом расписания
if not wait_for_panels(timeout=10):
    raise RuntimeError("panel_sse_not_ready")

# Для каждой регистрации после scan, перед confirm
record_confirmation_started(participant_id, perf_counter())
```

`participant_id` берётся из ответа scan. Передавать метку для ожидаемой регистрации.
В отдельной гонке обе стороны передают один ID. Используется первая метка, ожидается
одно изменение состояния участника и одно задание. Локальные отсчёты сравниваются
внутри одного процесса. Время доставки события в SSE считается от начала confirm,
поэтому включает время обработки confirm. Агент и браузер вносят отдельные измерения.

Для базовой серии разнести 300 участников по трём терминалам поровну.
Интервал каждого — 18 с, сдвиг между терминалами — 6 с. Для серии ×5 — 3,6 с
и 1,2 с соответственно. Гонка идёт на отдельном участнике. Сохранять отдельный run ID
и отдельный CSV для каждой серии. Пример `assignments.csv` имеет столбцы
`external_id,terminal_index,order`.

## Результаты

`--csv` сохраняет стандартные метрики Locust. В `RS_LOAD_SAMPLES` сохраняются
измерения с устройством, ID участника для SSE, порогом, статусом и признаком превышения.
В итоговой таблице считать p95 ближайшего ранга и максимум для успешных измерений,
отдельно выводить общее n, ошибки и превышения. Не складывать два учёта одной операции
из Locust HTTP и отдельной серии S06. При выключении панели отсутствующие события отмечаются
как ошибки, если запрос начался после первого снимка и истёк лимит ожидания. Сверить,
что у каждой панели есть один результат для каждого ожидаемого подтверждения.

`panel_search_api_ms` и `panel_sse_update_ms` относятся к API. В отчёте отдельно
указывать время до отображения в браузере и время до начала печати. Фиксировать SHA,
версию Locust, конфигурацию стенда и число устройств.
