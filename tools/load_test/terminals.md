# Терминалы и агенты S-06

Сценарий подключается к `panels.py` и `s06_metrics.py` Б1 в одном процессе Locust 2.47.0. Запускайте его на изолированной базе с синтетическими участниками. Три терминала используют отдельные токены и отдельные очереди. Три фоновых агента получают задания и подтверждают результат через API без отправки в спулер.

## Входы

- `RS_LOAD_ASSIGNMENTS` указывает на CSV со столбцами `external_id,terminal_index,order`. Распределите 300 разных участников поровну по терминалам 1–3. У каждого участника должен быть код, который распознаёт настроенное на стенде правило сканирования.
- `RS_LOAD_TERMINAL_1_TOKEN`, `RS_LOAD_AGENT_1_TOKEN` и переменные для устройств 2 и 3 указывают на заранее заведённые пары. У конференции с бейджами должен быть назначен рабочий шаблон.
- `RS_LOAD_RACE_EXTERNAL_ID` задаёт отдельного участника для гонки двух терминалов после основной серии. Этот ID отсутствует в CSV.
- Для каждого прогона задайте отдельные `RS_LOAD_RUN_ID`, `RS_LOAD_SCENARIO` и `RS_LOAD_SAMPLES`. Для LAN с собственным CA задайте путь к PEM в `RS_LOAD_CA`.
- Параметры сессий двух панелей и сбор общего CSV описаны в README Б1. Перед графиком терминалы ждут по одному начальному снимку SSE от обеих панелей до 10 секунд. Если снимка нет, прогон фиксирует ошибку подготовки. Минимальный прогрев по умолчанию равен 10 секундам. При необходимости увеличьте `RS_LOAD_START_DELAY_S` и добавьте столько же времени к запуску.

## Запуск

После объединения файлов задайте `PYTHONPATH` с каталогом `tools/load_test`. Если задачи находятся в разных клонах, укажите оба каталога в `PYTHONPATH` и путь к `panels.py` из клона Б1.

```sh
RS_LOAD_RATE_MULTIPLIER=1 locust -f tools/load_test/panels.py,tools/load_test/terminals.py --headless -u 5 -r 5 -t 1825s --host "$RS_LOAD_HOST" --csv "$RS_LOAD_CSV_PREFIX"
```

Для базовой серии терминалы работают с интервалом 18 с и сдвигом 6 с. После восстановления исходного состояния тестовой БД запустите отдельную серию с `RS_LOAD_RATE_MULTIPLIER=5` и `-t 385s`. Интервал будет 3,6 с, сдвиг 1,2 с. Не используйте один CSV результатов для двух серий.

## Замеры

`terminal_scan_api_ms` измеряется от отправки scan до разбора ответа API, порог 2000 мс. Отдельно записываются `terminal_confirm_api_ms`, `agent_confirm_to_claim_api_ms` и `agent_result_api_ms`. Подтверждение агентом в этом прогоне синтетическое. Порог 3000 мс относится к физическому началу печати, его измеряют на стенде по меткам «нажатие» и «принтер начал печатать».

В общем CSV проверьте число операций и ошибок по устройствам, p95 ближайшего ранга, максимум и нарушения заданных порогов. Сверьте отсутствие дублей регистрации и заданий по БД. Для гонки должны получиться две попытки, одна регистрация и одно задание. Для каждой ожидаемой регистрации обе панели должны записать по одному результату SSE.
